# QA Learning Hub (baga-net)

Внутренний инструмент для онбординга и отслеживания обучения QA-тестировщиков: фиксированный курс из 10 лекций, кастомные курсы от тимлидов с пререквизитами, система проверки задач по чек-листам с аналитикой, и лёгкая геймификация (баг-коины, косметика профиля).

## Стек технологий

### Frontend
- React 18 + TypeScript
- Vite (сборщик), код разбит на ленивые чанки по страницам
- Tailwind CSS
- React Router 6
- Axios
- Vitest + React Testing Library (тесты)

### Backend
- Node.js + Express
- SQLite3 (better-sqlite3)
- JWT (access + revocable refresh-токены)
- bcryptjs (хеширование паролей)
- Helmet + rate-limiting (базовая защита)
- Vitest + Supertest (тесты)

## Функции

### Аутентификация и роли
- Самостоятельная регистрация (email + пароль + имя) — новый аккаунт всегда начинается с роли `tester`
- JWT access-токен (короткий TTL) + отзываемый refresh-токен, с автообновлением на клиенте
- Роли валидируются на уровне приложения (`server/src/roles.js`), не жёстко зашитым в БД списком — добавление новой роли (например, для дизайнера или контент-менеджера) не требует миграции схемы
- `admin` — отдельная роль для управления пользователями (`/admin` в интерфейсе): назначает/меняет роль любому аккаунту, включая повышение до `lead`. `admin` неявно имеет доступ ко всему, что доступно `lead` (см. `requireRole()` в `auth.js`), так что это не нужно дублировать в каждом эндпоинте
- Пока нет сброса пароля по email (только сам пользователь меняет свой пароль будучи залогиненным — эта часть ещё не реализована; см. известные ограничения)

### Telegram
- Вход/регистрация через Telegram-бота: кнопка «Войти через Telegram» на страницах входа и регистрации открывает одноразовую deep-ссылку (`t.me/<bot>?start=<token>`) — бот подтверждает личность через `/start`, страница получает сессию поллингом. Первый контакт от нового Telegram-аккаунта **авторегистрирует** тестировщика (роль `tester` по умолчанию), как и обычная регистрация — Telegram-username подхватывается автоматически и обновляется при каждом входе, если человек его сменил
- Уже существующий (email/пароль) аккаунт может привязать Telegram отдельно — через выпадающее меню аккаунта в шапке («🔗 Привязать Telegram»), тем же deep-link-потоком, но без выдачи новой сессии
- Привязанный Telegram — основной канал уведомлений (подтверждение регистрации, оповещение о новом входе, смена роли админом). SMTP — резервный канал, используется только если Telegram не привязан; при отсутствии обоих уведомление молча пропускается, ничего не ломая
- Полностью отключаемо: без `TELEGRAM_BOT_TOKEN` в `server/.env` кнопка входа через Telegram сама скрывается, а серверные эндпоинты отвечают 503 вместо падения

### Мониторинг и аналитика
- Sentry (сервер + клиент) — отслеживание ошибок. На сервере через `logError()` (`server/src/sentry.js`) вместо голого `console.error` в каждом обработчике — большинство роутов сами ловят исключение и отвечают напрямую, не давая ему дойти до Express-обработчика ошибок, поэтому `logError()` — единственная точка, откуда Sentry вообще увидит эти ошибки. На клиенте — через `ErrorBoundary` и `monitoring.ts`
- PostHog (только клиент) — продуктовая аналитика: pageview + autocapture из коробки, плюс `identify()` при логине (id/роль), так что события можно разбивать по роли
- Оба — no-op без переменных окружения (`SENTRY_DSN` / `VITE_SENTRY_DSN` / `VITE_POSTHOG_KEY`) — ничего не включится и не потребует ключей, чтобы просто запустить проект локально

### Кабинет тестировщика («Моя нора»)
- Профиль с аватаром (base64 в БД), никнеймом, статусом
- Метрики: завершено лекций, средняя оценка, рост навыков
- 10 базовых лекций со статусами (заблокирована / активна / пройдена), разблокировка по цепочке при оценке ≥60%
- Кастомные курсы от тимлидов — с гибкими пререквизитами: нет / рекомендация (не блокирует) / обязательно (блокирует до прохождения указанного урока), проверяется и на клиенте, и на сервере
- Карточки и бейджи за пройденные лекции, крафт бейджа за полный набор карточек по навыку

### Система тестирования
- Лекция: 5–7 вопросов с мгновенной обратной связью и объяснением
- Прогресс сохраняется на сервере, не только в localStorage

### Чек-листы
- Тимлид импортирует шаблон чек-листа из Excel
- Тестировщик заполняет и отправляет чек-лист по задаче
- Общая, видимая всей команде история проверок с фильтрами и постраничной подгрузкой («Загрузить ещё»)
- Аналитика по частым ошибкам, авторам контента/вёрстки, тестировщикам

### Dashboard тимлида («Улей»)
- Таблица команды: прогресс, средняя оценка, рост навыков, активность
- Вкладка «До/После»: сравнение базовых и текущих оценок по 5 навыкам (HTML-структура, чтение CSS, DevTools, ошибки консоли, качество баг-репортов)
- Лента активности команды
- Аналитика по лекциям и по чек-листам

### Конструктор курсов (тимлид)
- Создание/редактирование кастомных курсов: модули → уроки (текст или тест), пререквизиты
- Сохранение — по diff, а не пересозданием: прогресс тестировщиков по уже пройденным урокам не сбрасывается при правке курса
- Проверка конфликта одновременного редактирования с подтверждением перед перезаписью

### Онбординг
- Контекстные подсказки при первом входе (по ролям, разово)
- Отдельная страница «Помощь» (FAQ) — доступна в любой момент

## Структура проекта

```
/client                 # React-приложение (Vite + TypeScript)
  /src/pages             # Страницы
  /src/components        # Общие компоненты
  /src/api.ts             # HTTP-клиент
  /src/auth.ts             # Сессии, refresh-токены
/server
  /db
    schema.js            # Схема БД + миграции + индексы
    seed.js               # Тестовые данные
    migrate_html_course.mjs  # Разовый перенос курса "Основы HTML" (безопасно перезапускать)
  /src
    app.js               # Все роуты API
    auth.js               # JWT + middleware
    index.js              # Точка входа
  /test                   # Серверные тесты (Vitest + Supertest)
```

## Быстрый запуск

```bash
npm install                       # корень (concurrently)
cd server && npm install && cd .. # backend-зависимости
cd client && npm install && cd .. # frontend-зависимости

cp server/.env.example server/.env   # задать JWT_SECRET, см. файл
cd server && npm run seed && cd ..   # создать БД с тестовыми данными

npm run dev                       # запускает сервер и клиент вместе
```

- Frontend: http://localhost:5173
- Backend: http://localhost:5001

## Скрипты

```bash
npm run dev              # сервер + клиент вместе
npm run dev:server       # только backend
npm run dev:client       # только frontend
npm run seed             # заполнить БД тестовыми данными
npm run build             # собрать обе части
```

В `client/` и `server/` также есть `npm test` (Vitest).

## Известные ограничения

- Нет сброса пароля по email и нет смены пароля для уже залогиненного пользователя (у аккаунтов, созданных через Telegram, пароля вообще нет — вход только через Telegram)
- Аватары хранятся как base64 в БД (осознанное решение, объектное хранилище — в будущем)
- SQLite — однопроцессный, без горизонтального масштабирования (осознанно, соответствует текущему масштабу использования)
- Нет аналитики использования — решения об улучшениях пока принимаются без количественных данных
